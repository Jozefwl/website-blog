## Short description
Personal website. The homepage is a server rack: each unit (About, Projects, Services, Contact) has status LEDs
driven by live Uptime Kuma data. Click a unit and it slides out, then opens its page.

- **Frontend:** Vite + React (static build, no server-side rendering), React Router, Motion for the drawer animation.
- **Backend (`server/`):** Express. `/metrics` (Prometheus CPU/RAM) and `/status` (Uptime Kuma proxy, because
  Uptime Kuma sends no CORS headers).
- **Production image:** `cgr.dev/chainguard/node` running `serve.mjs` (Node built-ins only) over `dist/`.

## Project layout
```
src/
  main.jsx, App.jsx        entry + routes
  components/layout/       Navbar, CookieNotice, Socials, Layout
  components/rack/         Rack, RackUnit, StatusLed, LcdClock, MetricsUnit, Gauge
  components/common/       AnimatedText, Infobox, Imagebox, LinkCard, ProjectCard, WeatherWidget
  pages/                   Home, About, Projects, Services, Contact, NotFound
  hooks/                   useNow, useMetrics, useServiceStatus
  lib/                     pure helpers (tested)
  data/                    rack units -> monitor IDs, projects, services, slides
serve.mjs                  static server + security headers (CSP etc.)
```

## Develop
Node >= 24.15.0 (`.nvmrc`).
```bash
npm install
npm run dev                # http://localhost:3000
# use a local backend instead of metrics.waldhauser.sk:
VITE_BACKEND_URL=http://localhost:5000 npm run dev
npm run build && npm test  # tests need the build (serve.mjs tests read dist/)
```

## Rack LEDs
Edit `src/data/rackUnits.js` to choose which Uptime Kuma monitor IDs light which unit.
Colours: green = up, red = down, amber = pending, blue = maintenance, off = no data.

## Rack model + textures
The rack is CSS 3D (no WebGL) and follows the 19" rack standard (EIA-310): 1U = 44.45 mm,
panels 482.6 mm wide, 3 rail holes per U, in a 600 mm wide cabinet with a perforated door.
Textures in `public/textures/` (~11 KB total) are generated by `scripts/generate-textures.py`
(own work, CC0). Re-run it to tweak them.

## env variables
Backend: `PROMETHEUS_URL`, `NODE_LABELS_JSON`, `UPTIME_KUMA_URL`, `UPTIME_KUMA_SLUG`
Frontend (build time, optional): `VITE_BACKEND_URL`

## Build and push
Frontend (linux x86_64):
```bash
docker buildx build --platform linux/amd64 -t harbor.waldoserver.top/cloud/website-blog:latest --push .
```

Backend (linux x86_64):
```bash
docker buildx build --platform linux/amd64 -f server/Dockerfile -t harbor.waldoserver.top/cloud/metrics-api:latest --push server
```
